# AGENTS.md

This repository is a Python package that wraps a React library as a Reflex
component. The package lives in `src/reflex_component_template/`; `demo/` is a
Reflex app for trying it.

## Commands

| Task | Command |
|---|---|
| Install | `uv sync` |
| Lint, format, type-check | `uv run pre-commit run --all-files` |
| Test | `uv run pytest` |
| Build (generates `.pyi` stubs) | `uv build` |
| Run the demo | `cd demo && uv run reflex run` |
| Check the demo compiles | `cd demo && uv run reflex compile` |

Run the lint and test commands before every commit.

## How the component is defined

- A component is a subclass of `rx.Component` in its own module (the example
  is `color_picker.py`). Do not name a module `component.py`, `app.py` or any
  other name in `EXCLUDED_FILES` in `reflex_base.utils.pyi_generator`: the
  stub generator skips those files silently.
- `library` is the npm package, always pinned to a version
  (`"some-lib@1.2.3"`), and `tag` is the name it exports the component under.
- Set `is_default = True` when the package default-exports the component.
- Props are `rx.Var[...]` class attributes. Reflex sends snake_case names to
  React as camelCase, so `max_value` becomes `maxValue`.
- Events are `rx.EventHandler[spec]` attributes. The spec maps the JavaScript
  event's arguments to what the Python handler receives
  (`rx.event.no_args_event_spec`, `rx.event.passthrough_event_spec(str)`, or a
  lambda).
- Subclass `rx.NoSSRComponent` instead when the library touches `window` or
  `document` at import time.
- Export the component and its `create` function from `__init__.py`.
- Prefer libraries that ship an ES module build (`module` or `exports.import`
  in their `package.json`). A CommonJS-only package can compile and then crash
  at render with "Element type is invalid ... got: object", so always load the
  demo in a browser after changing `library` or `tag`.

Reference: https://reflex.dev/docs/wrapping-react/overview/

## Stubs

`.pyi` files are generated by the `hatch-reflex-pyi` build hook during
`uv build` so editors see each prop as a keyword argument. They are not
committed; do not write them by hand.

## Tests

Tests live in `tests/` and check what the component imports and how it renders
(`str(component)` is the generated JSX). Add a test for each new prop or event.

## Releasing

Versions come from git tags. Pushing a tag `vX.Y.Z` runs
`.github/workflows/publish.yml`, which builds and publishes to PyPI through
trusted publishing.
